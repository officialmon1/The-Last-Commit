# Leaderboard function

The online leaderboard of the fastest escapes lives in **Neon Postgres**, in the Neon project `lennys-leaderboard`
(`purple-mud-20909476`, region `aws-us-east-2`). The game never connects to the database itself: this folder is a
tiny **Neon Function** deployed next to that database, and the game (`Assets/Scripts/Ruins/Leaderboard.cs`) only calls
the function's public URL. So there are no credentials anywhere in the repo or the build.

| Request | Body | Reply |
| --- | --- | --- |
| `GET /` | – | `{ "entries": [ { "name", "seconds", "created_at" }, … ], "rank": 0 }` – the 10 fastest escapes |
| `POST /` | `{ "name": "Lenny", "seconds": 754 }` | the same list plus `"rank"`: the position of the new escape among all escapes |

Rules enforced by the function: name 1–20 characters, seconds between 1 and 2160 (the 36-minute clock).

Table (created automatically on the first request, or run it yourself in the Neon SQL editor):

```sql
CREATE TABLE IF NOT EXISTS leaderboard (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  seconds integer NOT NULL CHECK (seconds > 0),
  created_at timestamptz NOT NULL DEFAULT now()
);
```

## Deploying a change

`index.mjs` has no dependencies (it talks to Postgres through Neon's HTTP SQL endpoint with `fetch`), so it deploys as-is:

```bash
npm i -g neon
neon auth
neon functions deploy leaderboard --src index.mjs --no-bundle --project-id purple-mud-20909476
```

The public URL stays the same across deploys (it is baked into `Leaderboard.BaseUrl` in the game).
